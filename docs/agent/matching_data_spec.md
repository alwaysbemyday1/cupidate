# Cupidate Matching Data Spec

## 1) 목적
- 매칭률 계산의 정확도/설명가능성/재현성을 보장하기 위한 프로필 및 선호도 데이터 표준을 정의한다.
- 본 문서는 매칭 엔진의 입력 계약(Contract)이며, UI/DB/도메인 로직의 공통 기준이다.

## 2) 사용자 프로필 입력 모델

### 2.1 기본정보 (필수)
- 이름/닉네임
- 생년월일 (나이는 파생값으로 계산)
- 성별
- 거주지역
- 휴대폰번호 (인증 여부 포함)
- 이메일 (인증 여부 포함)

### 2.2 외모정보
- 키 (cm)
- 체형
- 프로필 사진 (메인 1 + 추가 4~5)
- 외모 스타일 태그

### 2.3 개인신상정보
- 직업/직무
- 학력/학교
- 연봉/경제력 구간
- 결혼경력
- 자녀유무/계획
- 가족관계

### 2.4 생활정보
- 종교
- 흡연여부
- 음주여부
- 운동/건강관리
- 반려동물
- 주거형태

### 2.5 성격/취향정보
- MBTI
- 성격특성 태그
- 취미/관심사 태그
- 이상형(자유기술 + 구조화 필드)
- 연애관/결혼관

### 2.6 인증정보 (선택)
- 학교/직장 인증
- 소득/재산 인증
- 신분증 인증
- SNS 연동
- 추천인 인증

### 2.7 소셜정보
- 지인 차단 설정
- 프라이버시 공개 범위
- 매칭 선호사항

## 3) 이상형/선호사항 입력 모델

### 3.1 기본조건
- 나이 범위
- 거주지역(복수)
- 키 범위
- 체형 선호

### 3.2 외모조건
- 외모 스타일
- 헤어 스타일
- 패션 스타일

### 3.3 사회적조건
- 직업군
- 학력 수준
- 경제력 범위
- 사회적 지위(선택)

### 3.4 생활방식
- 흡연 선호
- 음주 선호
- 종교 선호
- 운동/취미 선호

### 3.5 성격/가치관
- MBTI 선호
- 가치관
- 연애스타일

### 3.6 관계조건
- 결혼 의사
- 자녀 계획
- 만남 목적

### 3.7 기타조건
- 거리 범위(km)
- 기타 특별조건(자유입력)

## 4) 정규화 및 검증 규칙
- 생년월일 -> 나이 파생 계산 (서버 기준 연도 고정)
- 문자열 태그는 trim + lowercase + dedupe
- 범위 필드(min/max)는 자동 정렬 및 도메인 경계값 클램프
- 단위 표준화: 키(cm), 거리(km), 연봉(구간 코드)
- 공개 범위/차단 설정은 매칭 후보 생성 이전에 하드 필터로 먼저 적용
- 인증 항목은 boolean + verified_at 타임스탬프로 관리

## 5) 매칭률 계산 상세

### 5.1 하드 필터 (불일치 시 즉시 탈락)
- 성별/성적지향 매칭 불가 조합
- 나이 하드 범위 불일치
- 차단 관계 존재
- 공개 범위/프라이버시 조건 불충족
- Cupid 네트워크 비연결 관계

### 5.2 가중치 점수 (0~100)
- 기본조건 적합도: 25
- 생활방식 적합도: 20
- 성격/가치관 적합도: 20
- 취미/관심사 공통성: 15
- 사회적조건 적합도: 10
- 외모/스타일 선호도: 10

### 5.3 보정치
- 인증 신뢰도 보너스: 최대 +5
- 프로필 완성도 보너스: 최대 +5
- 최근 활동성 보너스: 최대 +3

### 5.4 결과 설명 필드
- 최종 점수
- 카테고리별 부분 점수
- 강점 태그(예: 취미 3개 일치)
- 약점 태그(예: 거리 범위 초과 위험)
- 계산 시각/버전

## 6) 데이터 최소 완성 기준 (MVP)
- 필수 기본정보 100% 입력
- 생활정보 주요 항목(흡연/음주/종교) 입력
- 취미 태그 3개 이상
- 선호조건 기본 4종(나이/지역/키/흡연) 입력

## 7) 구현 순서
- Step 1: 입력 스키마 + 검증/정규화 레이어 구현
- Step 2: 매칭 점수 정책(하드필터 + 가중치 + 보정치) 구현
- Step 3: 매칭 결과 설명 모델 및 API 응답 포맷 구현
- Step 4: Matching/Home/Cupid View에 점진 연동
